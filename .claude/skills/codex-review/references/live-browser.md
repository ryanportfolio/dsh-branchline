# Live browser review

Mandatory read from Step 3 of [../SKILL.md](../SKILL.md) when the user asks for or approves a live browser for the reviewer. "The scope prompt" means the per-scope external-review prompts in [launch-example.md](launch-example.md); "Step 4" is SKILL.md Step 4.

A read-only reviewer cannot launch Chrome itself: the sandbox blocks the profile write, the child process and localhost network. Keep the sandbox and hand it a browser through an MCP server instead; the server is Codex's own child process, so the reviewer drives pages through tools while its shell stays read-only. Verified on codex-cli 0.156.1 with hand-built flags; through the runner it is unverified so far.

1. Launch headed Chrome on the real GPU with a CDP port, through the project's placed-window launcher where one exists (for example `launchPlacedChrome({ place: 'offscreen', args: ['--remote-debugging-port=9338'] })` from `scripts/lib/launch-chrome.mjs`), in a small script that keeps it open until the reviews finish. Pick a port with no listener before launch (`netstat -ano`, `lsof -i`), then confirm `http://127.0.0.1:<port>/json/version` answers from the Chrome you launched: an answer from an older process means the reviewer would attach to that session. This costs no usage.
2. Run the runner **without** `--review` (plain `codex exec`; MCP use under review mode is unverified), with the prompt passed by `--prompt-file`. Start from the scope prompt that matches the scope (branch, commit, or uncommitted with its untracked-file steps); replace the external-review sentence with the checks to run live and the URLs to compare, and keep the leaf rules. Open the prompt with a browser check: navigate to one page, evaluate one expression, and stop with the exact error if the tools fail. That keeps the smoke test inside the one authorized run. Add `--expect-diff` as usual.
3. Add the server per run with repeated `--config` flags (the runner passes each as `-c`; nothing is written to `config.toml`, and user MCP servers stay off):
   `--config 'mcp_servers.pw.command="npx"' --config 'mcp_servers.pw.args=["@playwright/mcp@latest","--cdp-endpoint","http://127.0.0.1:9338","--output-dir","<image dir>"]' --config 'mcp_servers.pw.default_tools_approval_mode="approve"'`
   - Use a server name that is not in the user's `config.toml` (`codex mcp list`): the runner disables every enabled user server by name after the caller's flags, so a clashing name gets switched off.
   - Exec mode's approval policy is `never`, so without `default_tools_approval_mode="approve"` every browser call fails with `MCP tool call requires approval, but approval policy is never`. The setting covers this one server only, and it also approves clicks and form submissions. Give the reviewer a fresh throwaway profile on local or test URLs only, never a signed-in or production app, and say in the prompt not to submit forms or change data. Valid values: `auto`, `prompt`, `writes`, `approve`.
   - The `--config` value is TOML, so write Windows paths with forward slashes (`D:/captures`); a backslash starts an escape and breaks the value. `--output-dir` places only auto-named captures; a screenshot given a relative filename lands in the reviewed workspace and changes its state. Tell the reviewer to omit filenames or pass absolute paths inside the image directory.
   - Keep `--sandbox read-only` (the default). Never loosen it for the browser.
4. Give each reviewer its own browser: one Chrome per reviewer on its own CDP port, or close and relaunch between runs. A reused browser carries the previous reviewer's tabs, cookies and storage into the next review.

A plain `codex exec` run has no review mode, so Step 4 collects it differently. There is no `ExitedReviewMode`, no review sibling and no `review-output.json`; the `result.json` `evidence` comes from the run's own rollout (`reviewSiblings` absent is expected). `$RUN/codex/last.md` is the reviewer's final message and holds its findings. `evidence.diffReads` gives scope identity, and `evidence.spawnCalls` counts spawned agents (plain exec exposes agent tools; a nonzero count breaks the leaf rules and bills extra runs, so disclose it). The runner does not count browser calls: count `item.completed` events whose `item.type` is `mcp_tool_call` in `$RUN/codex/events.jsonl`, with their `status` (completed or failed). Zero completed browser calls means the live checks did not happen: report the review as diff-only when `evidence.diffReads` is at least 1, and as incomplete when it is not (a failed opening browser check stops the reviewer before the diff). Attribute the rubric as a custom prompt.
